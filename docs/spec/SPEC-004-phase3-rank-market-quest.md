# [SPEC-004]: Phase 3 — 職位晉升 / 集市鑄造 / 任務系統

| 欄位 | 內容 |
|------|------|
| **狀態** | `Draft`（依賴 ADR-001 FIRM；含 schema v4 變更）|
| **日期** | 2026-07-22 |
| **關聯** | ADR-001、SPEC-002/003；借鏡「武林英雄」單機養成（職位/集市/任務），**不含多人競技** |

---

## Goal（這個功能建了什麼）

為「這就是武林」加入三項單機養成深度：**職位晉升**（以聲望逐階晉升，≥12 階，每階有封號與獎勵）、**集市 + 鑄造**（商店擴為多店鋪，消耗材料鑄造更強裝備）、**任務系統**（主線/支線任務，完成給獎勵並指引方向）。存檔升至 v4 並自動遷移 v1–v3。不動現有「闖蕩」機制。

## Inputs

- **玩家操作**：晉升職位、於集市購買、鑄造裝備、接受/繳交任務。格式：UI 事件。
- **新增資料表**：`ranks.ts`（職位階級）、`materials.ts`（鑄造材料）、`recipes.ts`（鑄造配方）、`quests.ts`（任務）。
- **既有存檔**：啟動讀 localStorage；v1–v3 → 遷移。

## Outputs

- **成功路徑**：
  - 職位：聲望達門檻可晉升，職位提升、領取一次性獎勵（銀兩/屬性/道具），封號顯示於角色面板。
  - 集市：多店鋪（武器/防具/藥鋪/材料鋪）分類選購；鑄造：消耗材料 + 銀兩打造裝備入背包。
  - 任務：可接任務、進度隨行動自動推進（如擊敗 N 敵、達某等級），達成後繳交領獎。
- **失敗路徑**：
  - 聲望不足晉升 → 拒絕、提示差距。
  - 鑄造材料/銀兩不足 → 拒絕、不扣資源。
  - 繳交未完成任務 → 拒絕。

## Side Effects（狀態變更）

- **Character schema 擴充**：新增 `rankId`（當前職位）、`materials`（Record<string, number> 材料庫存）、`quests`（{ questId: { accepted, progress, done } } 或精簡結構）。
- **存檔 v3 → v4**：`SAVE_VERSION = 4`；`migrateCharacter` 補新欄位預設（rankId 為最低階、空材料、空任務）。維持「只補不刪、冪等」。
- **任務進度推進**：行動（練功/闖蕩/戰鬥勝利）後檢查並更新任務進度（純函式）。
- **無外部網路呼叫**。

## Edge Cases

- v1–v3 存檔遷移至 v4：舊進度保留，新欄位補預設；冪等。
- 職位為線性階級：晉升只能逐階或跳至已符合的最高階；不得跳過未達門檻者；已達頂階不再晉升。
- 鑄造材料數量邊界：用最後一份後移除；不得為負。
- 鑄造配方指向不存在的產出/材料 id → 安全跳過、提示，不 crash。
- 任務重複接受 → 冪等（已接受不重複）；重複繳交已完成任務 → 拒絕。
- 任務進度型別多樣（擊敗數/等級/持有物）→ 各有純函式判定，達標為二元。
- 空資料表（無任務/無配方）→ UI 顯示「暫無」，不 crash。
- 晉升獎勵含永久加屬性時 → 同步重算 maxHp。

## Done When（二元可測試）

- [ ] 聲望達門檻可晉升職位，職位提升並發放一次性獎勵；純函式 `promote`/`rankFor` + 測試（含剛好達標、跳階、頂階）。
- [ ] 聲望不足晉升被拒（測試覆蓋）。
- [ ] 職位 ≥ 12 階，各有封號；封號顯示於角色面板。
- [ ] 集市多店鋪分類呈現；可購買各類商品。
- [ ] 鑄造：消耗材料 + 銀兩產出裝備入背包；材料/銀兩不足被拒（純函式 `craft` + 測試）。
- [ ] 材料 ≥6、鑄造配方 ≥4（資料表計數可驗）。
- [ ] 任務：可接任務、行動推進進度、達成後繳交領獎；純函式 `acceptQuest`/`advanceQuests`/`claimQuest` + 測試。
- [ ] 任務 ≥6，涵蓋至少兩種進度類型（擊敗數、等級/聲望門檻）。
- [ ] 存檔 v3→v4 自動遷移並正常遊玩；`migrateCharacter` 測試含 v3→v4（補預設、冪等）。
- [ ] `npm test` 全綠、`typecheck` exit 0、核心 coverage ≥ 80%。
- [ ] 真實瀏覽器 E2E：晉升職位、集市鑄造、接任務→推進→繳交 可實際操作。

## Non-Goals

- 不做多人競技（演武廳 PvP、武館踢館、師徒、奴隸、國家對戰）。
- 不做地圖化闖蕩（現有隨機闖蕩保留；地圖另議）。
- 不做鑄造的強化/失敗率/機率產出（先為確定性配方）。
- 不做任務的分支選擇（先為線性目標；分支可後續）。
- 不做後端、帳號。

## Rollback Plan

引入 schema v4（migration）。策略同前：
1. 程式回滾 = `git revert`。
2. migration 只補欄位不刪 v1–v3 既有欄位 → 回滾到舊版仍可讀舊欄位。
3. v4 存檔在只認 v3 的舊程式被「版本較新」邏輯拒絕載入（既有保護），不損毀。

---

## 實作順序（依賴驅動，非驗收條件）

1. schema v4 + 遷移（地基）。
2. 職位晉升：`ranks.ts` + `promote`/`rankFor` 純函式 + 測試 + 接聲望 + UI 顯示封號。
3. 材料 + 鑄造：`materials.ts`/`recipes.ts` + `craft` + 測試 + 集市多店鋪 UI（含鑄造鋪）。
4. 任務：`quests.ts` + accept/advance/claim 純函式 + 測試 + 行動後推進 + 任務面板 UI。
5. E2E 擴充驗證。
